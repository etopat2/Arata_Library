# Arata TechLibrary REST API design contract

`openapi.v1.yaml` is the standalone OpenAPI 3.1 contract for `/api/v1`. It has no dependency on the ignored source specification packages at build time. `design_operation_inventory.json` preserves the 102 Step 1 route candidates; `operation_additions.py` adds SRS workflows absent from that candidate. The source SRS remains authoritative and unchanged.

Most domains remain a **design contract**, not a running API. `billing_runtime.py`, `entitlement_runtime.py`, and `institution_runtime.py` overlay the implemented routes and their DTOs, policy requirements and SRS anchors onto that design inventory. The institutional overlay covers 32 live operations, including tenant-scoped manager and central-approval boundaries. The stub remains test-only and never connects to a database, DNS or payment provider. Live gateway sandbox and institutional IdP conformance remain separate release checks.

## Artifacts

| Artifact | Use |
|---|---|
| `openapi.v1.yaml` | Versioned paths, concrete closed DTOs, examples, standard errors and per-operation extensions; implemented billing, entitlement and institution routes have runtime overlays |
| `generated/v1.ts` | Strict TypeScript request and response types generated by `openapi-typescript` |
| `policies.v1.yaml` | Deny-by-default action policies for every operation |
| `POLICY_MATRIX.csv` | Reviewable roles, ownership, institution, entitlement, content, MFA and approval matrix |

| `REQUIREMENT_COVERAGE.md` | Direct versus indirect SRS coverage; no requirement is waived |
| `ERROR_CATALOGUE.md` | Stable problem codes and handling rules |
| `VALIDATION_REPORT.md` | Commands, results and implementation limits |

## Contract rules for service implementers

1. Load `policies.v1.yaml` into one server-side authorization service. Resolve all policy inputs from trusted session, database, payment, editorial and research services. Never trust UI state, `X-Stub-Context`, or client-declared roles, ownership, consent or entitlements.
2. Apply authorization to each object and action before reading protected content, returning a list item, issuing a private asset URL, starting a job or exporting data. Filter tenant scope in the query as well as evaluating returned objects. Default to deny if a policy, actor, publication state or evidence record is unavailable.
3. For cookie-authenticated mutations, enforce `X-CSRF-Token` bound to the session. Design-stage high-risk operations require recent action-bound `X-Step-Up-Token`, a reason and, where specified, distinct approver evidence. Implemented finance routes currently use recent MFA evidence in the server-held session, explicit `BILLING_*` permissions and independent refund/dispute reviewers; their exact controls are recorded in the billing overlay. Enforce the exact current revision, payment state and disclosure snapshot when relevant.
4. Treat `Idempotency-Key` as actor + operation + key + canonical request hash. Replay the original result for a matching body and reject a changed body with 409. Webhooks use a separately verified provider event identifier as the idempotency scope.
5. Respond with `application/problem+json` and stable `code` values. Do not reveal account existence, private institution membership, unpublished drafts, restricted research records or raw protected asset locations through errors or list metadata.
6. Public insight responses use `PublicInsight`, whose fields exclude private study/report/export and identity records. Only immutable reviewed snapshots may be marked released. Public-free resources can be opened anonymously after the server has resolved the effective public-free state and action permission.
7. Rate limits in the contract are proposed conservative per-minute starting values; operators must approve and tune them against SRS performance and abuse requirements before release. The service must enforce per-actor and source limits at the edge and at sensitive workflows.

## Rebuild and test

Install Python packages from `requirements-contract.txt` into an isolated environment and run `npm ci`. Then:

```sh
python api/build_contracts.py
python api/build_coverage.py
python api/validate_contracts.py
npm run api:types
npm run typecheck
python -m pytest -q api/tests
```

The documentation reconciliation generator reads the ignored source packages locally. After changing requirement anchors, run `python Documentation/Implementation/build_reconciliation.py` in the source workspace, then `--check`. CI validates the committed matrix without the ignored internal documents.

## Open implementation decisions

The billing adapter uses Flutterwave v3's `verif-hash` and independently verifies every payment through the server API; `apps/api/BILLING.md` records the sandbox and live activation gates. Other provider contracts remain future adapters. Real SSO profiles, institutional proof, approved refund terms, disclosure thresholds, retention periods, AI provider, code execution backend, and approved rate limits require configuration or accountable decisions. See `Documentation/Implementation/BLOCKERS.md` and `DECISIONS.md`.
