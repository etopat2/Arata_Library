# Unified access entitlements

This module implements the entitlement portion of `FR-ENT-001`–`006`, `FR-ENT-009`, `FR-ENT-017`, `FR-PAY-011`, `FR-INS-005`–`008`, and `BR-001`–`006`. The SRS is the baseline, but its formal sign-off is pending. The source SRS and implementation contracts are kept locally and are not published with this repository.

## How an access decision works

The reader first requires the current published edition or resource. It resolves the inherited content policy, queries only current source-backed entitlements, and matches every independent grant to the requested library, collection, publication, volume, edition or resource. Public-free content requires no account; registered-free content requires an active session. Premium content needs at least one matching active source. A revoked, suspended, future or expired grant never cancels a separate valid grant. Reader asset delivery rechecks the policy and entitlement when a short-lived token is redeemed.

`app."EffectiveEntitlement"` filters account and source state at UTC request time. `EntitlementService.effective()` maps collection membership and applies the pure scope resolver. Reader, resource, search and protected asset paths use this service. A protected decision inserts an `AccessDecisionLog` row with only user ID, target ID, action, decision, reason code and optional matching grant ID; it stores no email, IP address, request body or rendered content. The active security policy supplies the retention window.

Paid grants remain owned by billing and require a matching verified paid order. Trials require an active verified account, an enabled trial policy and no prior `TrialUsage`. Complimentary and institutional grants start pending and require a different administrator with the appropriate role, permission and recent MFA. Institutional access additionally requires an approved institution, exact approved email domain, current approved eligibility review, verified membership, approved agreement, active policy and capacity. Sponsored access also requires a current cohort membership. Bulk campaigns issue separate individual grants after independent approval. A free promotional code is random, stored only as a SHA-256 digest, shown once on creation, independently approved and redeemed once per verified account under a row lock and capacity limit. Paid gift codes remain unimplemented pending a verified purchase, refund and fraud workflow.

## API and administrator use

All routes are under `/api/v1`; exact DTOs and policy metadata are in `api/openapi.v1.yaml` and `api/policies.v1.yaml`. The `entitlements`, `access-grants`, `trial-admin` and `institution-access` screens cover own access, recipient search, grant requests and history, expiry monitoring, bulk/free-code campaigns and agreement requests. Each sensitive admin mutation uses CSRF, `SYSTEM_ADMIN`, a specific `ENTITLEMENT_*` permission and MFA verified within five minutes. A creator cannot approve their own grant, campaign or agreement. The account UI does not grant any authority by itself.

The institutional grant path consumes verified memberships, domains and reviews. It does not create or verify them; the full institutional enrollment and evidence-review workflow remains a separate S13 task. The default platform policy disables trials and institution benefits until an approved policy version and required business evidence are present. Complimentary scope and duration limits come from the active policy snapshot. An extension creates a new pending grant instead of altering the original validity period.

## Operations and recovery

Apply `202610270006_unified_entitlements`, `202610270007_entitlement_source_guards` and `202610270008_paid_entitlement_recovery` in order with `npm run db:migrate:deploy`, then `npm run db:grant:dev`. They add tables, enum values, constraints, triggers and a current-source view; they do not delete existing data. The last migration preserves paid billing dispute recovery and grace-period adjustments while retaining manual-grant immutability. Review existing rows and take a database backup before applying in any environment with user data. Never reset a database to roll back. For a failed rollout, stop entitlement writes, restore from a verified backup in an isolated database, inspect the migration record and write a corrective forward migration. The generated physical ERD is `database/erd/arata-physical.svg`.

The API runs bounded expiry notices and decision-log retention every 15 minutes outside tests. Set `ENTITLEMENT_JOBS_ENABLED=0` only when a separately scheduled process owns these tasks. Access expires immediately by UTC query even if a notice run is delayed. Manual maintenance is restricted to an MFA-verified administrator. Pending and successful grant changes are audited and recorded in append-only grant events.

Run `npm run db:test`, `npm run test:foundation`, `npm run api:validate`, `npm run api:test`, `npm run typecheck:foundation`, `npm run lint`, and `npm run build:foundation`. Development and test databases remain isolated. No production credentials or real charges are required for these checks.
