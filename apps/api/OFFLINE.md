# Offline reading implementation

The reader's service worker caches the versioned application shell and static assets. `/api/` uses network-only delivery, and the service worker does not cache reader responses, licence responses, notes, or protected downloads.

## Licence and package flow

An authenticated reader requests a device-bound licence for one published edition. The API checks the current publication revision, effective entitlement, inherited `allowOffline` decision, platform licence duration, and licensed-device limit before issuing it. The response lists only permitted lesson IDs and is signed with an ephemeral Ed25519 key. The browser verifies the signature and manifest digest, fetches each currently permitted lesson with `no-store`, and stores content encrypted with a non-extractable AES-GCM key held in IndexedDB. Lesson attachments are stored only if both offline and original-download policy permit them; binary files are capped at 25 MiB per file. Larger files are deferred. Browser quota estimates are checked before download, `QuotaExceededError` preserves a resumable partial package, per-package byte totals are shown, and the user can remove completed packages. Browser storage eviction remains under browser control; there is no platform-defined aggregate package-size setting yet.

The browser presents local expiry and clock rollback warnings, refuses expired packages, queues reader state changes while offline, and submits idempotent sync batches after connectivity returns. Notes, bookmarks and progress are encrypted in IndexedDB. A one-time migration encrypts pending queue entries from the previous local schema; a migration failure is surfaced in the reader and does not delete the old entries. The server rechecks the current licence, reader authorization, ownership and content policy at each sync. Duplicate operation IDs with the same payload return the saved result; reuse with a different payload is rejected. Conflicting progress is presented for a user choice. Notes are encrypted at rest again by the API.

The API exposes `POST/GET/DELETE /api/v1/reader/offline-licenses` and `POST /api/v1/reader/sync`. Creation requires an idempotency key; mutations require the normal authenticated session and CSRF token. Device identifiers are HMAC-hashed before storage. License rows bind user, device hash, edition and revision; sync records are unique per user/client operation.

## Security and operating limits

The package key is browser-managed, non-extractable WebCrypto material, not a DRM boundary. An owner of the device can inspect rendered content or browser storage. A public key delivered with an individual signed licence detects accidental corruption but is not a root of trust against a device owner who can modify IndexedDB. Device time rollback is detected using the last observed wall clock and signed server time, but a client clock and disconnected device are not trustworthy hardware. Revocation and policy changes take effect on reconnect; no client can learn about a remote change while disconnected. The app does not claim to block OS screenshots or all copying.

Offline research-event collection and offline exercise scoring are intentionally not enabled. Research consent, offline event intake and a dedicated offline assessment contract are not available in the running service. Low-bandwidth preference and full offline media transcoding are also not implemented; large attachments remain deferred. These items remain tracked as open requirements rather than implied support.

## Migration and recovery

Migration `202610280001_offline_license_idempotency` adds an idempotency key and request hash to `OfflineLicence` with a unique `(userId, idempotencyKey)` constraint. It is additive and does not delete reader data. Deploy with `npm run db:migrate:deploy`; verify with `npm run db:migrate:status` and `npm run db:verify`. For application rollback, roll back the application binary but leave this additive schema in place; prior code ignores the new columns. Do not reverse the migration after any licence has been issued because dropping the index/columns removes idempotency history. In a disposable environment before issuance, an operator may reverse it by dropping `OfflineLicence_userId_idempotencyKey_key`, then `idempotencyKey` and `requestHash`. If a deployment or data recovery is required, restore the normal PostgreSQL backup into a separate database, verify migration history and role grants, and only then perform a controlled cutover; do not reset or overwrite the existing database. Removing local packages is per-device and does not delete server notes, bookmarks or account history. User deletion and configured retention continue through the existing database deletion path.

## Verification scope

Browser coverage uses Chromium at desktop and mobile viewports with network changes, simulated storage quota failure, time rollback and licence expiration. API integration covers issue/list/revoke, idempotency, conflicting reuse and sync-after-revoke denial. SQL tests cover licence and sync uniqueness. Safari and Firefox, real-device storage pressure, production key management, assistive technology review and cross-browser persistence require separate release verification.
