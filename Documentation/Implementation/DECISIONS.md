## Existing design decisions retained

The Step 1 `architecture_decisions.md` contains ADR-001–ADR-010 for modular monolith, database integrity, publication revisions, additive entitlements, private assets, verified payments, research separation, public snapshots, offline limitations, and versioned API. These are design guidance subject to SRS precedence and implementation validation.

## API contract decisions - 2026-10-23

| ID | Status | Evidence / conflict | Resolution |
|---|---|---|---|
| ADR-API-001 | Adopted for design | The Step 1 OpenAPI is a 102-operation candidate with 39 generic DTO gaps and missing explicit security on session routes. The SRS requires action-specific validation, server authorization and versioned contracts (`INT-001-005`, `SEC-001`). | Keep its routes as an inventory, add SRS-required operations, and generate a standalone OpenAPI 3.1 `/api/v1` contract with closed request DTOs, typed responses, explicit security and 190 policy entries. The candidate audit remains historical evidence. |
| ADR-API-002 | Adopted for design | SRS `BR-001/002/004/009/010/013/018` requires free access, additive entitlement, action policy and restricted research release. A cookie-only role check cannot express these conditions. | Use one deny-by-default policy vocabulary for role, ownership, institution, entitlement, action permission, MFA, purpose and independent approval. Allow anonymous opening only after server proof of public-free state and effective read permission. Do not trust UI visibility or client policy assertions. |
| ADR-API-003 | Adopted for design | The SRS requires gateway-version-specific callback authentication (`FR-PAY-005`, `INT-006`) but no gateway/API version is approved. A fabricated provider JSON/signature contract would be unsafe. | Contract raw webhook bytes plus provider path and signature header. Require adapter allowlisting, exact active signature verification, replay protection, server-to-server settlement and provider-event idempotency before state change. Gateway-specific payload schemas remain a provider integration deliverable. |
| ADR-API-004 | Adopted for design | SRS `BR-015/018` requires exact editorial revision and reviewed statistical snapshot release; the source candidate has generic action bodies. | Require expected content/snapshot hashes, review evidence, reasons and step-up controls on release operations. Bind release to current approved evidence transactionally. The API stub tests only the contract and policy shape; live workflow proof remains open. |
| ADR-API-005 | Adopted for design | The SRS covers standalone books, while the Step 1 route inventory creates editions only below a volume. | Add `POST /api/v1/admin/publications/{id}/editions` for standalone publications and retain volume-scoped edition creation for series. The service must reject the wrong parent kind. |
| ADR-API-006 | Proposed operational default | Source requirements mandate throttling and pagination but do not approve fixed limits. | Describe conservative rate buckets and a maximum page size of 100 in the contract as configurable starting values; performance and abuse tests must tune and approve production limits. |
| ADR-FND-001 | Adopted | The v1 contract contains 190 design operations while the current task requests a runnable foundation. | Implement the contracted public liveness and service-authenticated PostgreSQL readiness endpoints first. Keep every other design operation visibly unimplemented. The PWA displays real service status and does not imply catalogue, reader or account delivery. |
| ADR-FND-002 | Adopted | SRS FR-OFL-001/002 require an installable offline shell and prohibit public caching of protected originals. | Precache only the static PWA shell; use Workbox `NetworkOnly` for all `/api/*` requests. Store only a theme preference in IndexedDB. Protected offline licences and content sync remain separate feature work. |
| ADR-FND-003 | Adopted | Local Docker Desktop service is stopped, while PostgreSQL and authenticated WSL Redis are available. | Verify API, PWA and worker against those local services and run the isolated Compose image path in GitHub CI. Keep Docker credentials and generated service tokens in ignored local files. |
| ADR-FND-004 | Adopted | npm 10's normal peer resolver reports an inconsistent Vite/esbuild peer tree for this workspace, while its legacy peer mode installs the locked, audited graph. | Record `legacy-peer-deps=true` in `.npmrc` for reproducible `npm ci` across local, CI and Docker. Revisit this when the upstream plugin graph supports a clean default resolver. |
